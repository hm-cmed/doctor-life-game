# 白衣キャリアロード（プロトタイプ）

医師の人生――出生から中学受験、医学部、専門医、開業や大学院、結婚・子育て・介護、そして高齢期まで――を年齢とともに疑似体験する、ブラウザだけで動くシミュレーションゲームです。ビルドツール不要・サーバー不要で、GitHub Pages にそのまま公開できます。

設計の背景（コンセプト、パラメータ設計、著作権上の整理など）は別途まとめた「医師人生ロード：開発基礎資料」を参照してください。本リポジトリはその資料の「05 ライフステージ別分岐構造一覧」「06 データ構造設計」を実装したPhase 1プロトタイプです。

## 遊び方（ローカルで試す）

ビルド不要です。`index.html` をブラウザで直接開くだけで遊べます。

```
# リポジトリのルートで
open index.html          # macOS
# または
python3 -m http.server   # http://localhost:8000/ で確認する場合
```

## ファイル構成

```
doctor-life-game/
├── index.html            # 画面の骨組み（DOM構造）
├── css/
│   └── style.css         # 見た目（ライト/ダークテーマ対応）
├── data/                 # ★ コンテンツはここを編集するだけで拡張できる
│   ├── params.js         # パラメータ定義・初期値・都道府県・専門医リスト
│   ├── stages.js         # ライフステージごとの分岐・選択肢・ランダムイベント
│   └── endings.js        # エンディングの定義（8種の通常エンディング＋2種の強制エンディング）
└── js/
    ├── engine.js          # 進行管理（GameEngineクラス）。DOM操作は一切しない
    └── main.js             # 画面描画とクリック操作のハンドリング
```

`data/` 配下は普通の `.js` ファイル（JSONではない）です。効果計算に関数をそのまま書けるため、「健康が低いほど悪いイベントが起きやすい」といった条件付きの分岐も、素のJSONより柔軟に書けます。JSONではなくこの形にしているのは、GitHub Pagesや `file://` で直接開いたときに `fetch()` のCORS制限に引っかからないようにするためです。

## コンテンツの拡張のしかた

### 新しいランダムイベントを追加する

`data/stages.js` の該当ステージの `randomEvents` 配列に追記するだけです。

```js
{
  id: "my_new_event",
  chance: 0.25,                 // 数値、または function(state){ return 確率; }
  title: "イベント名",
  text: "状況説明",
  choices: [
    { label: "選択肢A", effects: { health: -5, familyBond: 3 } },
    { label: "選択肢B", effects: { money: -100000 }, flagsSet: { someFlag: true } },
  ],
}
```

### 新しい選択肢を追加する

ステージの `choices` 配列に追記します。`resolve(state)` は `{ effects, flags, message, next, endGame }` を返す関数です（`next` と `endGame` は特殊な遷移をしたいときだけ指定）。

```js
{
  id: "my_new_choice",
  label: "表示するボタンの文言",
  condition(state) { return true; },   // 省略可。falseなら選択肢自体が表示されない
  resolve(state) {
    return {
      effects: { clinicalSkill: 5, money: -100000 },
      flags: { someFlag: true },
      message: "結果として表示されるテキスト。",
    };
  },
},
```

### エンディングを追加・調整する

`data/endings.js` の `ENDING_ARCHETYPES` に、7つのステータス（`clinicalSkill` `reputation` `health` `familyBond` `network` `careerFulfillment` `moneyIndex`、いずれも0-100相当）の目標値 `target` を持つオブジェクトを追加します。ゲーム終了時、最終ステータスとの距離が最も近いアーキタイプが採用されます（`js/engine.js` の `_computeNearestEnding()`）。

各ステージ・エンディングの詳しい設計意図は基礎資料の「03 パラメータ設計」「04 エンディング設計」「05 ライフステージ別分岐構造一覧」を参照してください。

## GitHub Pages への公開手順

1. このフォルダの中身をGitHubの新規リポジトリにpushする（このフォルダはすでに `git init` 済みです。`git remote add origin <あなたのリポジトリURL>` → `git push -u origin main` でOK）。
2. GitHubのリポジトリ設定 → **Settings → Pages** で、公開元を `main` ブランチ・ルート（`/`）に設定する。
3. しばらくすると `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される。

## 動作確認について

`data/` 内のロジック（分岐・パラメータ計算・エンディング判定）は、ランダムな選択を繰り返す自動プレイを500回実行しても例外なく完走し、全8種の通常エンディング＋2種の強制エンディングいずれにも到達できることを確認済みです。また実際のHTML/CSS/JSをヘッドレスブラウザで操作し、出生から高齢期・エンディング表示までコンソールエラーなしで到達することも確認しています。

## 既知の制約・次にやること（Phase 2以降）

これはPhase 1（最小構成）のプロトタイプです。基礎資料の「07 技術実装方針」のロードマップに沿って、次のような拡張が想定されています。

- **内容の厚み**：各ステージの選択肢・ランダムイベントは最小セットです。実際にプレイして、分岐の増量や文章の調整を進めてください。
- **パラメータバランス**：資産やエンディングの到達しやすさは初期値です。特に「病院・診療所経営者」「燃え尽き症候群」エンディングは意図的に到達難度が高めに作られています（自動シミュレーションで到達は確認済みですが、体感バランスは要調整）。
- **プライベートイベントの並行レーン化**：現状、結婚・子育て・介護などは「キャリア分岐」ステージのランダムイベントとして実装する簡易構成です。設計資料が想定する「独立した並行イベントレーン」として作り込む場合は、`career_module` 以外のステージでも発生できるよう `randomEvents` の仕組みを全ステージ共通のグローバルイベントプールに拡張するのが次の一歩です。
- **生成AI拡張（任意）**：Google AI Studio / Gemini APIを使った動的イベント文生成やAIメンター対話は、別レイヤーとして後から追加する想定です（APIキーを扱うため、公開時はサーバー側プロキシが必要になります）。
